# 流程节点参数来源与引用设计

日期：2026-11-27
状态：已实现（2026-11-27）

## 1. 背景

当前流程的参数模型是“流程级参数 + 节点映射”：

- 流程先声明一组全局参数（`flows.params_json`）。
- 每个工具节点在 `mapping_json` 中把工具参数映射到流程参数或固定值。
- 同一个值被多个节点使用时，需要在流程级声明一次，再在每个节点分别映射。

这与实际使用方式不符：参数本质上是某个节点工具的参数，应该按节点配置；后续节点需要同一个值时，不应再声明一份流程参数，而应直接复用前序节点的参数。参考商业产品把参数配置放在“参数设置”步骤，每个参数选择来源，支持固定值、执行时输入和引用前序参数。

## 2. 目标

1. 参数配置下沉到每个工具节点的每个工具参数。
2. 每个参数支持四种来源：
   - 工具默认值
   - 固定值
   - 执行时输入
   - 引用上游节点参数
3. 执行时输入由节点配置自动汇总，同一个输入只询问一次；流程不再手工维护全局参数列表。
4. 引用是编译期解析，复用上游节点配置的参数值，不要求脚本提供运行时输出契约，执行引擎不改。
5. 旧流程自动兼容，旧定时任务不因参数模型变化而失效。
6. 第三步“参数设置”按参考图改成内联表格，配置路径清晰。

## 3. 非目标

- 不支持引用脚本运行时输出或解析 stdout 生成参数。
- 不新增“表格输出”步骤。
- 不实现参考图中的 CMDB 动态过滤器、快速查询策略等外部数据源；固定值只表示普通字面量。
- 不改变工具执行、主机执行、DAG 调度语义。

## 4. 术语

- **节点参数**：工具节点上某个工具参数（如 `pkg_path`）的配置。
- **参数绑定**：节点参数与来源之间的关系，继续存放在 `flow_nodes.mapping_json`。
- **流程输入**：由所有“执行时输入”绑定汇总出的执行参数；每个输入名和显示标题流程内唯一。
- **上游节点**：从开始节点到当前节点路径上的祖先节点。
- **引用**：下游节点参数复用上游节点参数的绑定和值，编译时解析。

## 5. 参数模型

### 5.1 来源

| 来源 | 存储 | 说明 |
|---|---|---|
| `default` | 不写 mapping | 使用工具参数默认值；必填且无默认值时保存报错 |
| `literal` | `source=literal` + `value` | 固定值；敏感参数不允许 |
| `input` | `source=input` + `input_name` + `input_label` | 执行时输入；输入名与显示标题流程内唯一 |
| `node` | `source=node` + `ref_node_id` + `ref_param` | 引用上游节点参数 |

“默认值”不落库，避免产生无意义映射；读取时 mapping 缺失即表示默认值。

### 5.2 绑定结构

沿用 `flow.Mapping`，扩展 JSON 字段：

```go
type Mapping struct {
    Source     string `json:"source"`                // literal | input | node
    Value      string `json:"value,omitempty"`       // literal 的值
    InputName      string `json:"input_name,omitempty"`      // input 的输入名
    InputLabel     string `json:"input_label,omitempty"`     // input 的显示标题
    InputSensitive bool   `json:"input_sensitive,omitempty"` // 旧流程参数敏感标记（兼容）
    RefNodeID      string `json:"ref_node_id,omitempty"`     // node 引用的节点
    RefParam       string `json:"ref_param,omitempty"`       // node 引用的参数名
}
```

旧数据中的 `{"source":"flow","value":"ENV"}` 在读取时转换为：

```json
{"source":"input","input_name":"ENV","input_label":"<旧参数显示名>"}
```

保存时统一写新结构。数据库不需要新增迁移，继续使用 `mapping_json`。

### 5.3 流程输入

`flows.params_json` 继续保存 `[]tool.Param`，但不再手工编辑，而是保存时由节点绑定推导：

- 只有 `source=input` 的绑定会产生流程输入。
- 每个 `source=input` 绑定必须使用流程内唯一的输入名和显示标题；任一重复即冲突，保存时报错。
- 下游节点需要复用同一个输入时，必须使用 `source=node` 引用上游参数，不能重复声明同名输入。
- 输入定义由工具参数自动带出：类型、必填、默认值、选项、敏感、说明。
- `InputLabel` 优先使用绑定里的显示标题，其次工具参数的显示名，最后输入名。
- 同一条输入可能被多个下游参数引用；引用不产生新的输入声明，必填、敏感按引用关系向上传播。
- 输入名必须符合现有环境变量名规则（`[A-Za-z_][A-Za-z0-9_]*`），不能以 `SPOOL_` 开头。
- 输入顺序按节点拓扑顺序、工具参数声明顺序稳定输出。

输入只在声明节点创建；其他节点通过引用复用，引用关系会随上游输入名修改自动更新。

`FlowInput.params` 字段保留用于兼容旧客户端：当 mapping 仍是旧 `flow` 来源时，用其中的定义补全输入标题、敏感、选项等；新式 `literal/input/node` 映射不使用这个字段，保存时以节点绑定推导结果为准。

## 6. 引用解析

### 6.1 允许范围

- 只能引用当前节点的**上游祖先节点**，不能引用自己、兄弟节点或下游节点。
- 祖先关系按流程图结构计算，不考虑边条件；条件分支是否执行不影响编译期取值。
- 引用目标必须是工具节点，且目标参数存在。

### 6.2 解析结果

对节点 `N` 的参数 `P`，递归解析绑定：

- 无绑定：结果为 `default`，值取工具参数默认值。
- `literal`：结果为 `literal`，值为固定值。
- `input`：结果为 `input`，输入名为 `input_name`。
- `node`：解析目标节点的目标参数，继承其结果；引用链可以有任意层。

解析结果包含：

- 根来源类型（default/literal/input）
- 固定值或输入名
- 是否敏感
- 是否必填

### 6.3 类型与值校验

- 引用目标参数与当前参数类型必须一致。
- select 类型还要求当前参数的选项覆盖目标参数的全部选项；否则保存报错，避免运行时值不合法。
- 引用链最终落到固定值或默认值时，固定值必须符合当前参数的类型和选项。
- 必填参数不能最终解析为空：
  - 没有绑定且工具参数无默认值：保存报错。
  - 引用链最终落到空默认值：保存报错。
  - 引用链最终落到执行输入：该输入自动标记必填。
- 解析时检测引用环；正常祖先校验下不会出现，数据异常时返回明确错误。

### 6.4 敏感值传播

- 工具参数本身敏感时，其来源必须是执行输入或工具默认值；不能使用固定值。
- 敏感参数引用上游参数时，引用链不能最终落到固定值或非敏感参数的默认值。
- 引用链上任意参数敏感，根输入自动标记敏感。
- 非敏感参数引用敏感参数时，值仍按敏感处理，不进入明文参数和日志。
- 输入被敏感参数直接或间接引用时，整个输入标记敏感。

## 7. 后端流程

### 7.1 保存流程

`Create` / `Update` 的校验顺序：

1. 规范化旧 `flow` 映射为 `input`：
   - 优先使用请求中的 `params` 定义；
   - 更新时使用流程已有的参数定义；
   - 都找不到时按工具参数自动生成。
2. 现有结构校验：名称、分类、节点、连线、DAG、主机、mapping 来源字段等。
3. 读取所有工具节点的最新工具版本参数。
4. 校验每个 mapping 的参数名存在于工具参数中。
5. 校验来源字段、类型、祖先关系、敏感规则、必填规则。
6. 解析所有节点参数，校验输入名/显示标题唯一，生成 `[]tool.Param`。
7. 用 `tool.ValidateParams` 校验生成的输入定义。
8. 保存 `params_json` 和节点 `mapping_json`。

旧流程更新时，未使用的旧全局参数不再写入 `params_json`；仍被 `flow` 映射引用的参数会转换为输入并保留。

### 7.2 读取流程

`Get` 返回前做两件事：

1. 把旧 `flow` 映射转换为 `input`，标题从流程参数定义中查找。
2. 过滤 `Flow.Params`，只保留被节点绑定引用的输入；未使用的历史参数不再出现在详情、执行弹窗和定时任务表单中。

列表接口不要求过滤，列表页不展示流程参数。

### 7.3 编译执行

`Compile` 使用同一套解析器：

1. 读取最新工具版本参数，构建解析器。
2. 解析每个节点参数，得到根来源。
3. 同时按当前工具参数重新推导流程输入定义；敏感、必填以当前推导结果为准，避免工具升级后旧定义导致敏感值落明文。
4. 根来源为 input 时取执行值，为 literal/default 时取解析值。
5. 按现有规则拆分明文参数和敏感参数，敏感 key 继续使用 `n.<nodeID>.<param>`。
6. 生成执行计划，执行引擎和 DAG 调度保持不变。

执行值校验使用第 3 步推导出的输入定义，忽略流程未声明的额外参数，兼容旧定时任务中已被清理的参数。工具执行仍保持严格校验。若工具升级新增了必填输入而执行表单尚未刷新，编译会返回明确的缺参错误，提示重新保存流程。

### 7.4 定时任务

- 流程输入来自 `flows.Get` 返回的输入定义，定时任务创建、编辑、执行自动使用。
- 流程目标的定时任务在校验时忽略已不存在的额外参数，避免旧任务因输入清理而无法保存或执行。
- 工具目标保持现有严格参数校验。

## 8. 前端界面

### 8.1 第一步：基本信息

- 移除“流程参数”编辑卡片。
- 保留名称、分类、描述、最大执行时长。

### 8.2 第二步：流程设计

- 流程图编辑不变。
- 节点抽屉移除“参数映射”，只保留节点名称、工具、执行主机、超时、重试。
- 抽屉中提示“参数在第三步配置”，可显示已配置参数数量。

### 8.3 第三步：参数设置

按参考图改为内联表格，节点按拓扑顺序排列：

```text
步骤参数                         流程输入：pkg_path（巡检包路径，string，必填）

A.解压（工具：deploy，2 台主机）
┌──────────┬────────┬──────────────┬────────────────────────────────────┐
│ 参数      │ 类型    │ 来源          │ 值 / 配置                           │
├──────────┼────────┼──────────────┼────────────────────────────────────┤
│ pkg_path │ string │ 执行时输入     │ 输入名 pkg_path · 标题 巡检包路径    │
│ user     │ string │ 固定值         │ root                               │
└──────────┴────────┴──────────────┴────────────────────────────────────┘

B.安装（工具：install，1 台主机）
┌──────────┬────────┬──────────────┬────────────────────────────────────┐
│ pkg_path │ string │ 引用上游参数   │ A.解压 / pkg_path                   │
└──────────┴────────┴──────────────┴────────────────────────────────────┘
```

交互规则：

- 节点块头部显示节点名、工具、执行主机数量，并提供“节点设置”打开原抽屉。
- 替换节点工具时清空该节点自己的参数映射；其他节点指向它的引用保留并在参数页标记失效，保存前必须修正。
- 删除节点时，指向它的下游引用标记失效，保存前必须修正。
- 参数行显示参数名、类型、必填/敏感标签。
- 来源下拉：工具默认值、固定值、执行时输入、引用上游参数。
- 敏感参数禁用固定值；没有类型兼容的上游参数时禁用引用来源并提示原因。
- 执行时输入：
  - 输入名和显示标题都必须流程内唯一，重复时在参数页和保存时提示冲突。
  - 输入名、显示标题直接编辑；需要复用时选择“引用上游参数”。
  - 类型、必填、敏感、默认值、选项只读展示，由工具参数和引用关系推导。
- 引用上游参数：
  - 先选上游节点，再选该节点类型兼容的参数。
  - 展示解析提示，例如“当前解析为执行输入 pkg_path”或“当前解析为固定值 /tmp”。
- 固定值按参数类型渲染控件：bool/select 用下拉，int 用数字输入，string 用文本框。
- 页面顶部展示流程输入汇总，包含输入名、标题、类型、必填、敏感和使用节点数。
- 保存前在前端做基础校验；后端仍做最终校验并返回中文错误。

### 8.4 执行弹窗与定时任务

- 继续使用 `Flow.Params`，因此无需改接口。
- 参数标题、说明、必填、敏感来自推导后的流程输入。
- 没有执行输入的流程不再显示参数区。
- 定时任务的目标参数表单同样自动只显示当前输入。

### 8.5 流程详情

- “流程参数”文案改为“流程输入”。
- 只展示当前被节点使用的输入；旧流程未使用的参数不显示。

## 9. 兼容性

- 不新增数据库迁移；映射继续存 JSON。
- 旧 `flow` 映射读取时转换，保存时写新结构；旧流程参数标记为敏感时保留输入敏感标记。
- 旧流程未使用的全局参数在保存时清理。
- 旧定时任务多传的额外参数在执行和流程定时任务校验时忽略，不影响运行。
- 旧执行历史不受影响，历史计划中已保存的节点参数仍然是解析后的值。
- 回滚到旧版本后，新结构中的 `input`/`node` 映射可能不被旧版本识别；发布说明需注明。

## 10. 测试与验收

### 10.1 后端测试

- 创建/更新流程时正确保存四种来源。
- 重复执行输入名、重复显示标题保存失败；下游引用同一输入不视为重复。
- 引用祖先节点成功；引用兄弟/下游/自己失败。
- 引用类型不一致失败；select 选项不覆盖失败。
- 链式引用解析到固定值、默认值、执行输入均正确。
- 必填参数未配置、引用空默认值失败。
- 敏感参数使用固定值、引用链落到固定值失败。
- 敏感输入在编译计划中进入敏感参数，不进入明文。
- 旧 `flow` 映射读取转换、保存清理、编译兼容。
- 流程编译忽略额外旧参数；定时任务流程目标忽略额外旧参数。

### 10.2 前端测试

- 工具函数测试：拓扑排序、祖先计算、输入推导、兼容参数筛选。
- 参数来源切换、引用失效提示、重复输入名/标题冲突提示的组件级测试（如现有测试基础允许）。

### 10.3 验收场景

1. 创建流程：
   - A 节点 `pkg_path` 来源执行输入，输入名 `pkg_path`，标题“巡检包路径”。
   - B 节点 `pkg_path` 引用 A。
   - C 节点 `work_dir` 固定值 `/tmp`。
   - D 节点 `work_dir` 引用 C。
2. 执行弹窗只出现 `pkg_path`，不出现 `work_dir`，也不为 B/D 重复询问。
3. 修改执行输入后，B 得到修改后的输入值，D 得到 C 的固定值 `/tmp`。
4. 将 A 的输入名改为 `package_path`，B 的引用提示自动更新，执行弹窗显示新输入名。
5. 旧流程打开后，旧 `flow` 映射显示为执行时输入；保存后未使用旧参数消失；旧定时任务仍可执行。
6. 类型不匹配、引用下游、敏感固定值等错误在保存时被拦截并显示中文提示。

## 11. 实现顺序建议

1. 后端模型与解析器：扩展 Mapping、祖先计算、参数解析、输入推导、校验。
2. 旧数据兼容：读取转换、保存清理、编译忽略额外参数、定时任务兼容。
3. 后端测试：解析、校验、编译、定时任务。
4. 前端类型与工具函数：绑定类型、拓扑/祖先、输入推导、兼容参数。
5. 第三步内联参数表格、第一步移除全局参数、节点抽屉调整。
6. 执行弹窗、流程详情、定时任务文案与展示适配。
7. 构建、全量测试、浏览器端到端验证。
